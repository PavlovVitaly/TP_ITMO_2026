Отчёт об ошибках: ai_tasks/broken_code/asset_roi_scoring.py

Проверка запуска

Запустил проверку синтаксиса:

`python3 -m py_compile ai_tasks/broken_code/asset_roi_scoring.py`

Python остановился с `IndentationError: unexpected indent` на строке 72. Пока синтаксические ошибки не исправлены, обычный запуск не дойдёт до исполнения сценариев. Ниже отдельно перечислены блокирующие синтаксис ошибки и проблемы, которые проявятся после их устранения.

Блокирующие ошибки запуска

1. Неверный отступ поля `DailyDigest.is_viewed` — строка 72

Фрагмент:

```python
    formation_date: date
    	is_viewed: bool = False
```

Перед `is_viewed` стоит табуляция, тогда как соседние поля используют пробелы. Проверка синтаксиса воспроизводит ошибку именно здесь.

Как исправить: выровнять поле с остальными атрибутами класса, используя обычные пробелы:

```python
    formation_date: date
    is_viewed: bool = False
```

2. Не импортированы `date` и `datetime` — строки 43 и 71

Фрагменты:

```python
    parsed_at: datetime
    formation_date: date
```

В начале файла импортированы `statistics`, `dataclass`, `field` и `Enum`, но не типы `date` и `datetime`. После исправления синтаксиса Python при создании класса `AssetAdvertisement` получит `NameError` на имени `datetime` в аннотации. До аннотации `date` выполнение в текущем порядке не дойдёт.

Как исправить: добавить импорт:

```python
from datetime import date, datetime
```

3. Разорвано обращение к методу — строки 161–162

Фрагмент:

```python
            base_rent_rate = self
            ._calculate_median_rent(exact_rent_ads)
```

Вызов метода отделён от `self` переносом строки. Точка в начале следующей строки не продолжает предыдущее выражение, поэтому файл не сможет быть разобран как Python-код.

Как исправить: записать вызов цельным выражением или заключить его в скобки:

```python
            base_rent_rate = self._calculate_median_rent(exact_rent_ads)
```

4. Сломана сборка и печать строки результата — строки 254–258

Фрагмент:

```python
            print()
                f"Объект #{ad.id} ..."
                f"Цена: {ad.price:,} руб. ..."
                f"ROI: {item.calculated_roi}% ..."
            )
```

`print()` уже завершён на первой строке, а следующие строки сдвинуты внутрь блока и не являются аргументами вызова. В текущем виде отступы приводят к синтаксической ошибке. Даже если просто убрать лишний отступ, текстовые литералы не будут переданы в `print()` и строка результата не выведется.

Как исправить: передать склеиваемые f-строки в один вызов `print()`:

```python
            print(
                f"Объект #{ad.id} ({ad.street}, д. {ad.house_number}) | "
                f"Цена: {ad.price:,} руб. | Аренда: {item.base_rent_rate:,} руб./мес. | "
                f"ROI: {item.calculated_roi}% ({item.calculation_method.value}){warning}"
            )
```

Логические ошибки после устранения ошибок запуска

5. Метод с названием «радиус 500 м» не измеряет расстояние — строки 128–137

Фрагмент:

```python
    def get_rent_ads_in_radius_500m(self, city: str, district: str, street: str):
        return [
            ad for ad in self._storage
            if ad.deal_type == DealType.RENT
            and ad.city.lower() == city.lower()
            and ad.district.lower() == district.lower()
        ]
```

Параметр `street` не используется, координат и расчёта расстояния нет. Поэтому результат — все объявления аренды в том же городе и районе, а не объекты в радиусе 500 метров. Медиана может быть рассчитана по объектам, находящимся намного дальше или в другой части района.

Как исправить: если требование действительно про 500 м, хранить координаты объектов и отбирать объявления по расстоянию до оцениваемого объекта; в метод передавать точку/объявление, от которого измеряется расстояние. Если координат в MVP нет, переименовать метод и пометку результата в соответствии с фактическим правилом — например, «по району», не выдавая его за радиус.

6. При полном отсутствии данных об аренде ноль выдаётся как рассчитанная ставка — строки 148–153, 164–169

Фрагмент:

```python
        if not rent_ads:
            return 0
```

Если для объекта нет аренды ни в том же доме, ни в резервной выборке, метод возвращает ставку `0`. Затем объект получает `CalculationMethod.RADIUS_500M` и ROI `0.0`, то есть выглядит как оценённый приблизительно, хотя данных для оценки не было.

Как исправить: различать «ставка равна нулю» и «данных нет». Например, возвращать `None` при пустой выборке, а вызывающий код — явно помечать объект как «недостаточно данных» и не сортировать его как рассчитанный ROI. Либо исключать такой объект из результатов, если это согласуется с требованиями.

7. Поиск аренды в том же доме может взять объявление из другого района или категории — строки 114–126

Фрагмент:

```python
            if ad.deal_type == DealType.RENT
            and ad.city.lower() == city.lower()
            and ad.street.lower() == street.lower()
            and ad.house_number == house_number
```

«Город + улица + номер дома» не всегда однозначно определяют один дом: в одном городе могут быть улицы с одинаковым названием в разных районах. Кроме того, условие не сравнивает категорию актива. При появлении других категорий в хранилище аренда, например, другого типа актива может попасть в оценку недвижимости.

Как исправить: сопоставлять аренду и продажу по одинаковой категории и однозначному идентификатору/адресу объекта; минимум — добавить район к адресу, если данных достаточно, и согласовать правила нормализации номера дома. Не считать одного совпадения улицы и номера гарантией, что это тот же дом.

Что исправлять в первую очередь

1. Исправить табуляцию в `DailyDigest` и восстановить выражение медианы и вызов `print()`.
2. Добавить импорт `date` и `datetime`.
3. Повторно запустить `py_compile`, затем запустить файл и проверить оба встроенных сценария.
4. Отдельно согласовать поведение при полном отсутствии данных и смысл запасного поиска; это изменения бизнес-логики, а не синтаксические починки.

Исходный файл не изменялся. Первая ошибка подтверждена запуском `py_compile`; остальные синтаксические и логические проблемы выявлены по указанным фрагментам исходника. После синтаксических ошибок сам файл пока нельзя полноценно проверить исполнением, поэтому для них не заявляется результат успешного запуска.
